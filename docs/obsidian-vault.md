# Obsidian 仓库模式（1.2.0-alpha.5 本机预览，尚未发布）

这一开发功能让 Obsidian 知识库中的 **PDF 与完整 Markdown 成为正式资料**。侧边栏自动显示已有 PDF，点击后原位阅读和批注，不复制、移动或改写这些源文件。也可导入外部 PDF：Paperdesk 将副本保存到知识库的 `Paperdesk/PDFs/`，保留外部原文件。文献笔记和批注保存在指定的 Paperdesk 文件夹，在知识库外保存可重建的索引。

本说明对应开发分支，不属于 **1.1.0-beta.5** 发布包。已有 SQLite 文献库仍可按原方式使用。旧 alpha.1／alpha.2 的复制式文献继续可读，原有 PDF 保留，不自动迁移。知识库 PDF 列表仅供选择，不自动关联文献或建立全文索引。

## 规则速查

| 内容或操作 | 规则 |
| --- | --- |
| 正式资料 | 保留已关联 PDF（原位置或导入副本）、带完整管理状态的文献 Markdown 和 `Library.md`；本机索引可重建 |
| 笔记正文 | 可在 Paperdesk 或 Obsidian 编辑；同一篇错开写，保存后再换另一边 |
| 标题、批注、书签、分类 | 在 Paperdesk 修改；保留 Markdown 的生成区和管理状态 |
| 文件与库结构 | 保留所选源 PDF 的位置和名称，以及管理笔记的 UUID 文件名；`Library.md` 由程序维护 |
| 冲突 | 自动保存暂停，先保留草稿；只有副本实际保存成功才算进入 `Notes/Conflicts/`，比较后手工合并正文 |
| 换设备 | 等 iCloud 等同步完成落地，再重新读取仓库并编辑；文件联动不提供全局锁 |
| 备份 | 正常退出后备份完整 Paperdesk 管理目录和全部所选源 PDF，同时保留库外恢复资料；备份整个知识库更方便 |

## 接入知识库

选择已经存在的 Obsidian 知识库根目录，也就是包含 `.obsidian/` 的目录。Paperdesk 在指定的单层子文件夹中管理文献笔记、批注和分类，默认名称为 `Paperdesk`。源 PDF 可留在知识库其他目录；未选择的 PDF 和其他笔记不会自动进入文献索引。

### 桌面开发版

1. 正常保存并退出正在使用的文献库。
2. 启动包含本功能的桌面开发版，在「文件 → 打开 Obsidian 仓库…」中选择知识库根目录。
3. 侧边栏自动显示知识库已有 PDF，直接点击开始阅读与批注；也可用「选择 Obsidian PDF」窗口按文件名或目录查找。应用记住所选知识库，下次启动使用同一位置。
4. 点击 Paperdesk 的「资料位置」，核对知识库、资料文件夹和文献数；选择文献后可用「在 Obsidian 中打开笔记」打开对应笔记。

普通的「打开已有文献库…」仍用于 SQLite 文献库。切换存储位置前须等待保存完成；关闭时保留现有的保存队列与草稿恢复保护。

两种模式都支持「导入 PDF」和拖入文件。仓库模式将导入副本保存到 `Paperdesk/PDFs/<UUID>.pdf`；普通文献库仍保存在自己的文献库。已有 Obsidian PDF 直接从侧边栏打开，或使用选择窗口；首次打开才新建关联笔记和全文索引。同一内容已关联时沿用已有来源、笔记和批注，不创建另一份关联。尚未打开的 PDF 可按文件名和目录查找；全文搜索和文献分类用于已关联文献。

### 源码浏览器版

准备依赖并构建当前开发源码后，启动时指定知识库根目录：

```sh
npm ci
npm run build
PAPERDESK_VAULT_DIR="/absolute/path/to/YourVault" \
PAPERDESK_VAULT_SUBDIR="Paperdesk" \
npm start
```

`PAPERDESK_VAULT_SUBDIR` 可省略。它必须是普通的单层目录名，不能包含路径分隔符、控制字符或以 `.` 开头。程序不会创建知识库根目录；请先在 Obsidian 建立知识库。

`PAPERDESK_DATA_DIR` 在此模式下指定**知识库外的本机缓存与翻译设置目录**，不再是 PDF 与笔记的正式位置。省略时，程序在系统用户数据目录的 `Paperdesk/vault-cache/` 下按库身份选择独立缓存。即使通过符号链接指向知识库内部，缓存位置也会被拒绝。不要把不同知识库指向同一个缓存。

服务继续只监听 `127.0.0.1`；存储模式不会新增网络上传或 AI 调用。翻译与 Codex 共享仍须由用户主动发起，并沿用原有内容边界。

## 正式文件与本机缓存

例如 PDF 可以仍放在原有的 `Papers/` 中。`<UUID>` 是 Paperdesk 管理笔记的稳定文献标识，不用它重命名源 PDF：

```text
YourVault/
  .obsidian/
  Papers/
    example.pdf
  Paperdesk/
    Library.md
    PDFs/
      <imported-UUID>.pdf
    Notes/
      <UUID>.md
      Conflicts/
        <conflict-copy>.md
```

| 内容 | 正式位置与用途 |
| --- | --- |
| 已有 PDF | 知识库中的所选原文件，例如 `Papers/example.pdf`；只读打开，不复制到 Paperdesk 文件夹 |
| 导入 PDF | 外部文件的副本，保存在 `PDFs/<UUID>.pdf`；外部原文件保留 |
| 文献笔记 | `Notes/<UUID>.md`，包含笔记正文、可读批注、页面书签和完整状态 |
| 分类与主题 | `Library.md`，保存单层分类和阅读皮肤等库状态 |
| 冲突副本 | `Notes/Conflicts/`，保留无法安全覆盖的笔记内容供核对 |
| 搜索索引 | 知识库外的 `paperdesk.sqlite`，从正式文件重建文献状态与提取文本 |
| 翻译与本机恢复资料 | 知识库外的缓存目录，包括 `translation.sqlite`、替换前副本及恢复记录；不会写入知识库 |

侧边栏和选择列表只枚举知识库内非隐藏目录中的普通 PDF，不跟随符号链接，最多列出 10,000 份；列表截断时会标明。启动、刷新和重新进入窗口时读取列表；界面也定期检查列表变化。显示文件不会自动关联、提取正文或生成笔记。只有你打开或导入的 PDF 才建立关联笔记和全文索引。临时上传与解析文件位于知识库外。

已关联的源 PDF 移动、改名或被替换后，Paperdesk 会停止读取并提示核对，不自动猜测新位置或重新绑定。保留原文件位置、名称和内容；需要恢复时从备份恢复所选原文件。旧预览版的 `Paperdesk/PDFs/<UUID>.pdf` 仍是对应旧文献的来源，请一并保留。

### Markdown 的编辑边界

文献笔记是普通 Markdown，同时承载 Paperdesk 恢复所需的完整状态。

- **笔记正文**可在 Paperdesk 或 Obsidian 编辑，支持原有 Markdown 内容。
- **frontmatter**包含可读文献信息；已有自定义属性会保留。
- **生成的批注区**用于在 Obsidian 阅读引文、评论和页码。批注的引文、页码、坐标、颜色等仍在 Paperdesk 修改。
- **隐藏的 JSON 状态**保存文献／批注 UUID、页面书签名称与实际页码、归一化矩形、元数据、请求重试记录与阅读位置写入顺序；`Library.md` 也有受管理的完整库状态。保留这些管理区，才能重建完整库。

frontmatter 中的标题等可读属性不会替代隐藏状态中的文献元数据；请在 Paperdesk 修改标题、分类和批注。不要只复制可见笔记正文后删除原文献 Markdown，也不要手工改 UUID、隐藏状态或生成批注结构。只有 PDF 和没有完整状态的普通笔记，不能恢复 Paperdesk 批注与分类。

生成批注的可见内容与正式状态不一致、管理标记或元数据受损、PDF 校验不匹配时，Paperdesk 拒绝读写并保留原文。已建立的库缺少 `Library.md` 时，会停止刷新和读写，不重建一份空分类覆盖原有安排。先从保留资料恢复完整文件，再重新读取仓库。文件格式在开发期仍可能调整；它不是任意 Obsidian 插件的通用批注协议。

## 个人页面书签

点击阅读工具栏的「书签」，在书签面板添加当前页；默认名称为「第 N 页」，可改名、删除和点击跳转。同一篇文献每个实际 PDF 页最多保存一条书签。书签与笔记一起保存到完整文献 Markdown，重开文献、重启应用或重建索引后仍可恢复，不写进原 PDF，也不依赖浏览器本机存储。页码固定指向实际 PDF 页，不应用目录的印刷页码偏移。详见 [页面书签](bookmarks.md)。

alpha.5 将本机索引升级到 schema 5，升级旧数据库前自动创建 SQLite 一致性备份，位于本机数据目录的 `recoveries/migrations/`。旧 v1/v2 文献 Markdown 继续读取，成功保存时写入 v3 并保留原位或导入来源。旧 alpha.4 无法读取新的完整状态；需要回退时正常退出并恢复升级前的完整管理文件与数据库备份。升级前正常退出并备份完整 Paperdesk 管理目录及库外数据目录。

## 两边编辑与冲突

在 Obsidian 保存笔记正文后，Paperdesk 会在当前阅读器的既有心跳中读回变化，通常约每 3 秒检查一次。启动时也会读取正式文件；需要主动核对时，在「资料位置」点击「重新读取仓库」。Paperdesk 无须运行 Obsidian 插件来读取文件；「在 Obsidian 中打开笔记」使用 Obsidian URI，需本机安装 Obsidian。

Paperdesk 正在编辑、排队保存或存在恢复草稿时，不会用外部正文直接替换输入。正常的笔记版本冲突会暂停自动保存，并尝试把草稿保存在 `Notes/Conflicts/`；只有实际写入并读回成功，才确认副本已保存。文件受损、磁盘失败或副本保存失败时，只能确认本机草稿仍被保留，不能据冲突提示认定知识库已有副本。不要把通信失败理解为文件没有保存。

遇到冲突按这四步处理：

1. 暂停这篇文献在另一边的编辑，保留当前窗口和草稿。
2. 文件受损或缺失时先恢复完整文件，再查看副本的保存结果。只有已确认的副本才算保存在 `Notes/Conflicts/`；未确认时先保留本机草稿。
3. 在 Paperdesk 点击「保留草稿并载入已保存笔记」，载入最新正文，再从保留草稿中比较、手工合并正文；保留生成批注区和管理状态。
4. 重新保存，确认显示「已保存到 Obsidian 仓库」，再继续编辑或换设备。

该机制保护同一本机服务中的读写，不提供多个 Paperdesk 进程、不同电脑或云同步客户端之间的全局锁。同一篇文献错开写；通过 iCloud 等服务同步知识库时，等文件完整落地后重新读取仓库，再换设备编辑。

## 备份与重建索引

正常停止 Paperdesk 后，备份完整 Paperdesk 管理目录，包括 `Library.md`、文献 Markdown、冲突副本和旧复制式文献的 PDF；同时备份所有已选择的源 PDF，并保留知识库外的恢复资料。直接备份整个知识库更方便。只备份管理目录而漏掉外部目录中的源 PDF，或只保存笔记可见正文，都不足以恢复完整文献。

需要重建索引时：

1. 正常停止 Paperdesk，确认其他窗口和服务也已退出。
2. 备份上述正式文件，并保留整个本机缓存目录作为恢复来源。
3. 将缓存中的 `paperdesk.sqlite` 及其同名 `-wal`／`-shm` 文件一起移到保留位置。只在服务停止后操作；不要修改知识库中的正式文件。
4. 使用同一知识库和子文件夹重新启动，等待文件读取与 PDF 文本提取完成，再核对文献数、笔记和批注。

只有文献索引可从正式文件重建。`translation.sqlite` 中的凭据、用量与翻译缓存，以及本机备份／恢复资料不属于重建范围；保留它们。缓存丢失也不等于最后一份尚未提交的浏览器草稿已经写入正式 Markdown。

## 当前支持范围

支持选择知识库已有 PDF 并原位阅读，以及已关联文献的搜索、批注、单层分类、主题和笔记正文联动；原有字符选区、页面坐标、幂等重试与阅读位置顺序保护继续适用。启动读取管理笔记并核对所选源 PDF，重建本机索引，完成后服务才就绪。

尚未提供旧 SQLite 库的一键迁移、未选择 PDF 的全文检索、任意 Markdown 自动关联、Obsidian PDF 内嵌批注互通、移动端 Paperdesk、云同步一致性或多设备协作。Obsidian 本身可以在其他设备打开同步过去的 PDF 与 Markdown，但这不代表 Paperdesk 已在该设备运行，或外部同步的同时写入已经过验证。

实现、自动测试、桌面实际操作与安装包验收应分别记录。本文说明开发功能的使用约定，不宣称该功能已发布或通过所有环境验收。
