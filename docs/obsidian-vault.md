# Obsidian 仓库模式（1.2.0-alpha.1 本机预览）

这一开发功能让 Obsidian 知识库中的 **PDF 与 Markdown 成为正式资料**。Paperdesk 负责阅读、批注和搜索，在知识库外保存可重建的索引；退出 Paperdesk 后仍可在 Obsidian 打开 PDF 和编辑笔记。

本说明对应开发分支，不属于 **1.1.0-beta.5** 发布包。已有 SQLite 文献库仍可按原方式使用。新模式不会自动搬迁旧库、扫描整个知识库或修改导入来源。

## 接入知识库

选择已经存在的 Obsidian 知识库根目录，也就是包含 `.obsidian/` 的目录。Paperdesk 只管理其中指定的一个单层子文件夹，默认名称为 `Paperdesk`；其他笔记和附件不在接入范围内。

### 桌面开发版

1. 正常保存并退出正在使用的文献库。
2. 启动包含本功能的桌面开发版，在「文件 → 打开 Obsidian 仓库…」中选择知识库根目录。
3. 在 Paperdesk 中导入 PDF，开始阅读与编辑。应用记住所选知识库，下次启动使用同一位置。
4. 点击 Paperdesk 的「资料位置」，核对知识库、资料文件夹和文献数；选择文献后可用「在 Obsidian 中打开笔记」打开对应笔记。

普通的「打开已有文献库…」仍用于 SQLite 文献库。切换存储位置前须等待保存完成；关闭时保留现有的保存队列与草稿恢复保护。

### 源码浏览器版

准备依赖并构建当前开发源码后，启动时指定知识库根目录：

```sh
npm ci
npm run build
PAPERDESK_VAULT_DIR="/absolute/path/to/YourVault" \
PAPERDESK_VAULT_SUBDIR="Paperdesk" \
npm start
```

`PAPERDESK_VAULT_SUBDIR` 可省略。它必须是普通的单层目录名，不能包含路径分隔符、控制字符或以 `.` 开头。程序不会创建知识库根目录；请先在 Obsidian 建立知识库。

`PAPERDESK_DATA_DIR` 在此模式下指定**知识库外的本机缓存与翻译设置目录**，不再是 PDF 与笔记的正式位置。省略时，程序在系统用户数据目录的 `Paperdesk/vault-cache/` 下按库身份选择独立缓存。即使通过符号链接指向知识库内部，缓存位置也会被拒绝。不要把不同知识库指向同一个缓存。

服务继续只监听 `127.0.0.1`；存储模式不会新增网络上传或 AI 调用。翻译与 Codex 共享仍须由用户主动发起，并沿用原有内容边界。

## 正式文件与本机缓存

默认结构如下，`<UUID>` 是稳定的文献标识，不以可变标题作为文件名：

```text
YourVault/
  .obsidian/
  Paperdesk/
    Library.md
    PDFs/
      <UUID>.pdf
    Notes/
      <UUID>.md
      Conflicts/
        <conflict-copy>.md
```

| 内容 | 正式位置与用途 |
| --- | --- |
| PDF | `PDFs/<UUID>.pdf`，保留导入字节；高亮、评论和笔记不改写 PDF |
| 文献笔记 | `Notes/<UUID>.md`，包含笔记正文、可读批注和完整状态 |
| 分类与主题 | `Library.md`，保存单层分类和阅读皮肤等库状态 |
| 冲突副本 | `Notes/Conflicts/`，保留无法安全覆盖的笔记内容供核对 |
| 搜索索引 | 知识库外的 `paperdesk.sqlite`，从正式文件重建文献状态与提取文本 |
| 翻译与本机恢复资料 | 知识库外的缓存目录，包括 `translation.sqlite`、替换前副本及恢复记录；不会写入知识库 |

导入会复制 PDF 到管理范围中，不移动或删除来源。既有资料请通过 Paperdesk 导入，逐步接入；把任意 PDF 或 Markdown 手工放进目录不等于完成导入。

### Markdown 的编辑边界

文献笔记是普通 Markdown，同时承载 Paperdesk 恢复所需的完整状态。

- **笔记正文**可在 Paperdesk 或 Obsidian 编辑，支持原有 Markdown 内容。
- **frontmatter**包含可读文献信息；已有自定义属性会保留。
- **生成的批注区**用于在 Obsidian 阅读引文、评论和页码。批注的引文、页码、坐标、颜色等仍在 Paperdesk 修改。
- **隐藏的 JSON 状态**保存文献／批注 UUID、归一化矩形、元数据、请求重试记录与阅读位置写入顺序；`Library.md` 也有受管理的完整库状态。保留这些管理区，才能重建完整库。

frontmatter 中的标题等可读属性不会替代隐藏状态中的文献元数据；请在 Paperdesk 修改标题、分类和批注。不要只复制可见笔记正文后删除原文献 Markdown，也不要手工改 UUID、隐藏状态或生成批注结构。只有 PDF 和没有完整状态的普通笔记，不能恢复 Paperdesk 批注与分类。损坏的管理标记、元数据或校验不匹配的 PDF 会阻止读写并提示核对，原文件不会被当成空笔记覆盖。文件格式在开发期仍可能调整；它不是任意 Obsidian 插件的通用批注协议。

## 两边编辑与冲突

在 Obsidian 保存笔记正文后，Paperdesk 会在当前阅读器的既有心跳中读回变化，通常约每 3 秒检查一次。启动时也会读取正式文件；需要主动核对时，在「资料位置」点击「重新读取仓库」。Paperdesk 无须运行 Obsidian 插件来读取文件；「在 Obsidian 中打开笔记」使用 Obsidian URI，需本机安装 Obsidian。

Paperdesk 正在编辑、排队保存或存在恢复草稿时，不会用外部正文直接替换输入。若两个版本不能安全接续，保存会提示冲突，并保留笔记内容与 `Notes/Conflicts/` 中的副本。先核对两份内容，再选择并重新保存所需版本；不会自动推断哪一份更正确。不要把通信失败理解为文件没有保存。

该机制保护同一本机服务中的读写，不提供多个 Paperdesk 进程、不同电脑或云同步客户端之间的全局锁。通过外部服务同步知识库时，请等文件完整落地，并避免同时在多台设备写同一文献。

## 备份与重建索引

正常停止 Paperdesk 后，备份整个受管理子文件夹，包括 `Library.md`、全部 PDF、文献 Markdown 和冲突副本。只备份 PDF 或笔记可见正文不足以恢复批注和库状态。知识库内的其他个人资料按原有 Obsidian 备份方式保存。

需要重建索引时：

1. 正常停止 Paperdesk，确认其他窗口和服务也已退出。
2. 备份上述正式文件，并保留整个本机缓存目录作为恢复来源。
3. 将缓存中的 `paperdesk.sqlite` 及其同名 `-wal`／`-shm` 文件一起移到保留位置。只在服务停止后操作；不要修改知识库中的正式文件。
4. 使用同一知识库和子文件夹重新启动，等待文件读取与 PDF 文本提取完成，再核对文献数、笔记和批注。

只有文献索引可从正式文件重建。`translation.sqlite` 中的凭据、用量与翻译缓存，以及本机备份／恢复资料不属于重建范围；保留它们。缓存丢失也不等于最后一份尚未提交的浏览器草稿已经写入正式 Markdown。

## 当前支持范围

支持指定子文件夹中的 PDF 导入、阅读、搜索、批注、单层分类、主题和笔记正文的文件联动；原有字符选区、页面坐标、幂等重试与阅读位置顺序保护继续适用。启动先读取正式文件并重建本机索引，完成后服务才就绪。

尚未提供旧 SQLite 库的一键迁移、整个知识库检索、任意 Markdown 自动关联、Obsidian PDF 内嵌批注互通、移动端 Paperdesk、云同步一致性或多设备协作。Obsidian 本身可以在其他设备打开同步过去的 PDF 与 Markdown，但这不代表 Paperdesk 已在该设备运行，或外部同步的同时写入已经过验证。

实现、自动测试、桌面实际操作与安装包验收应分别记录。本文说明开发功能的使用约定，不宣称该功能已发布或通过所有环境验收。
