# 开发指南

## 环境与首次安装

需要 Node.js 24.0.0 或更新版本，推荐 `.nvmrc` / `.node-version` 指定的 24 LTS。`package-lock.json` 固定依赖解析结果，首次安装依赖与 Chromium 需要网络。

```sh
npm ci
npx playwright install chromium
```

`npm ci` 安装项目依赖，Chromium 用于自动浏览器回归和 0.6.0 的专用 ChatGPT 连接；仅本地阅读而不使用自动问答时，可不启动这项浏览器功能。

VS Code 或兼容编辑器可打开根目录的 `PDF_Vibecoding.code-workspace`。其中任务对应开发启动、完整检查和日常启动，使用相同的 npm 入口。

## 启动方式

| 用途 | 命令 | 页面 | 默认文献库 |
| --- | --- | --- | --- |
| 开发 | `npm run dev` | `http://127.0.0.1:5173` | `.local/dev-data/` |
| 日常使用 | `npm run build` 后 `npm start` | `http://127.0.0.1:4317` | `data/` |
| Mac 日常使用 | 双击 `启动纸间.command` | `http://127.0.0.1:4317` | `data/` |

开发命令同时管理 Vite 界面和 4318 端口上的 API，结束时按 Control+C。界面固定使用严格端口 5173，冲突时停止并提示。不要为了消除报错随意终止不明进程。

| 环境变量 | 适用入口 | 含义 |
| --- | --- | --- |
| `DEV_API_PORT` | `npm run dev` | 修改开发 API 端口，默认 4318 |
| `DEV_DATA_DIR` | `npm run dev` | 修改开发文献库，默认 `.local/dev-data/` |
| `PORT` | `npm start` / Mac 启动器 | 修改日常使用端口，默认 4317 |
| `PAPERDESK_DATA_DIR` | `npm start` / Mac 启动器 | 修改正式文献库，默认 `data/` |
| `PAPERDESK_CHATGPT_ENGINE` | 本机 ChatGPT 执行器 | 默认 `managed-browser`；显式设为 `ego` 才启用旧 EGO 执行器，不自动降级 |
| `PAPERDESK_CHATGPT_PROFILE_DIR` | 专用浏览器 | 覆盖默认 `~/.config/paperdesk/chatgpt-browser/`；须为专门的本机目录，不使用日常浏览器或 EGO 配置 |
| `PAPERDESK_EGO_COMMAND` | 显式 EGO 执行器 | 覆盖 `ego-browser` 可执行程序，仅 `PAPERDESK_CHATGPT_ENGINE=ego` 时生效；不接受命令参数串 |

开发入口不继承生产 `PAPERDESK_DATA_DIR`，避免误写正式库。自定义库应位于项目的忽略目录或仓库外，不能放在 `src/`、`public/`、`dist/` 等源码或静态资源位置。按启动输出访问对应地址。

Mac 启动器会在缺少依赖或构建产物时准备运行；已有 `dist/` 时不会自动判断源码是否更新，因此修改代码后应重新 `npm run build`。跨平台入口为 npm 命令；Mac 的一键启动脚本不代表 Windows/Linux 已完成验收。

## 检查

| 命令 | 范围 |
| --- | --- |
| `npm test` / `npm run test:api` | API 集成测试 |
| `npm run build` | 准备本地 PDF 资源并构建生产界面 |
| `npm run test:browser` | Chromium 浏览器回归；需要已有生产构建 |
| `npm run check` | 依次执行 API 测试、生产构建和浏览器回归 |
| `npm run plugin:setup` | 核对当前阅读服务，绑定仓库外的本机插件配置 |
| `npm run plugin:install` | 完成绑定并向本机 Codex 安装/启用 Paperdesk 插件 |

API 与浏览器测试使用自有临时文献库和随机端口，不连接常驻正式库。自动浏览器检查包括 17 项选文回归，以及示例导入、单一笔记保存、导出与刷新恢复；目录回归使用原创生成 PDF，检查多级书签、折叠、筛选、正确跳页、窄窗面板互斥、笔记搜索、文献切换及手动／自动页码校正。另现场生成超过 50 MiB 的原创 PDF，通过文件选择器实际导入与渲染，防止旧文件大小限制回归；大文件不会作为二进制材料提交。CI 使用 Node.js 24，并安装 Chromium 后运行完整检查；工作流存在不等于当前提交已通过远端运行。

笔记兼容回归先用 API 写入旧版两个非空字段，验证单个编辑区完整显示、未修改保存及导出不写回旧字段；编辑后统一保存，再刷新检查无重复。缺少基准版本的旧格式草稿恢复后先保留并核对，不自动覆盖新笔记；独立草稿位置、历史恢复入口和并发归档均经浏览器检查。历史保存竞态脚本的编辑器名称已同步为“笔记”，其运行仍需要原定的隔离浏览器工具环境。

开发服务启动后可打开 `/tests/selection-harness.html`，点击 “Run selection tests” 单独查看选文结果；此页不访问文献库。旧的 `tests/notes-race.browser.mjs` 属于特定浏览器工具环境的历史辅助脚本，不应直接对正式笔记运行。

涉及视觉位置或复杂 PDF 的变更，还需用可共享材料人工核对实际引文和高亮位置。仅查看历史通过记录不能替代检查当前分支。

区域回归使用原创生成的两页纯图形 PDF，确保没有隐藏文字层；通过真实指针覆盖正反拖选、小框与取消、预览保存、编辑、搜索、导出、刷新、页面跳转，以及缩放／收起文献栏后的坐标一致性。另验证文献栏状态恢复与搜索快捷键。文字批注通过真实 PDF 拖选和保存继续验证，不能仅依靠 17 项 DOM 选区测试代替集成流程。

插件回归使用独立资料库：API 检查会话过期、隐藏/多窗口行为、PNG 校验、笔记版本冲突、旧字段和幂等重试；MCP 通过真实 stdio client 启动临时安装缓存，核对工具和资源、身份错误、分页及文本/图片返回。新增浏览器流程验证主动共享、切页取消、外部追加刷新、保存队列与冲突草稿恢复。模拟宿主测试只验证面板协议，不替代当前 Codex 的原生显示验收。具体步骤见 [Codex 插件](codex-plugin.md)。

## 自动 ChatGPT 连接开发

0.6.0 的浏览器与原生面板通过本机任务 API 提交冻结的问题／选区，再显示进度；当前预览保持打开时直接显示完整只读“ChatGPT 回答预览”，“查看回答”保留为回看／复制入口。`server/chatgpt-jobs.mjs` 管理单执行队列、持久化 journal 与幂等；`server/chatgpt-runner.mjs` 默认选择专用浏览器执行器，`server/chatgpt-browser.mjs` 管理独立 Chromium 配置和窗口；`server/chatgpt-ego.mjs` 保留任务拥有权和发送／取回答的共用流程，文件名不代表默认需要 EGO。原生面板的任务与连接工具分别使用 `_meta.chatgptJob` 和 `_meta.chatgptConnection`，不经 Codex 模型生成回答。

真实连接使用项目已准备的 Chromium，不要求独立 EGO。专用配置默认位于 `~/.config/paperdesk/chatgpt-browser/`，与正式 PDF 库及日常 Chrome／EGO 分开；不要读取、迁移或提交其中的登录资料。通过连接窗口完成登录，不自动输入凭据。发送前核对真实 UI 的 Chat、Latest、Extra High（xhigh）；缺失、不明确、验证码、登录或用户控制均需要暂停处理，不自动降级、绕过验证或读取其他会话。不要把自动回归当作连接真实账号的授权。

可针对性运行隔离协议检查：

```sh
node --test tests/chatgpt-jobs.test.mjs tests/chatgpt-runner.test.mjs tests/plugin-mcp.test.mjs
```

这些测试应使用替代执行器、原创材料和临时库；浏览器／原生集成验证冻结快照、同 UUID 查回、用户明确继续、旧任务保留、连接打开／关闭与执行中关闭冲突、服务端继承的追问、完整多段回答内联显示、关闭／翻页不强开旧回答、回答隔离与手动备用方式。最终仍运行 `npm run check`，但测试命令列在这里不表示当前分支已通过，结果见 [0.6.0 记录](history/codex-plugin-0.6.0.md)。真实文字发送、扫描图上传、完整回答自动取回及实际客户端显示必须分别验收，不能用页面已有回答替代取回完成。

任务内容位于当前文献库 `chatgpt-jobs/`，包括输入、回答、执行 ledger 和 PNG，目录权限为 0700，journal、输入与执行 ledger 为 0600，上传用 PNG 快照为只读 0400。journal 最多保留 8 份完整任务，淘汰后仍保留轻量请求凭据防止重发；不要为了让测试通过删除正式任务记录。任务无取消 API；关闭预览或面板不会取消执行。连接关闭在执行中会返回 409；服务停止则关闭专用浏览器并保守保留未确认任务，仍不会撤回已发出的问题。服务重启不会重新派发未确认任务；网页／面板新实例暂不自动恢复旧任务列表。原 PDF、笔记与数据库 schema 保持不变。

## 目录与数据纪律

```text
src/                  界面与阅读交互
server/               本地 API 和存储
scripts/              启动与资源准备
tests/                回归测试与测试材料
public/examples/      可共享的原创阅读示例
plugins/paperdesk/     本机 Codex 插件源码
.agents/plugins/      本仓库插件市场定义
docs/                 项目背景、架构和开发说明
data/                 正式文献库，不提交
.local/               开发数据、迁移清单和备份，不提交
dist/                 生成的生产界面，不提交
public/pdf-assets/    生成的 PDF.js 资源，不提交
```

提交前检查暂存内容。Git 忽略规则不能阻止所有人为误操作，不要使用强制添加把私人文件带入版本历史。开发库和测试库只放可丢弃的材料。

备份或恢复前正常停止使用该文献库的服务，再复制完整目录。若必须在服务运行时备份，使用 SQLite 在线备份机制并验证数据库与其引用的 PDF 一致。迁移细节和个人来源记录保存在 `.local/`。

schema 2 增加批注类型。首次启动新版前备份旧库；自动迁移在事务中执行，旧批注默认 `text`，重复启动不重复修改。应用不降级更高版本数据库。回退旧程序需要恢复升级前备份，不要手工删列或只修改 `user_version`。

## 常见情况

- **端口已被占用：** 确认端口由哪个项目使用；停止正确的旧实例后再启动，避免在旧代码或旧文献库上误操作。
- **界面尚未构建：** 日常使用先运行 `npm run build`；开发使用 `npm run dev` 显示的地址。
- **浏览器回归缺少 Chromium：** 运行 `npx playwright install chromium` 后重试。
- **笔记保存失败：** 保留当前窗口，检查服务、磁盘空间和权限，恢复后确认“已保存到本机”；草稿提示不等于正式保存成功。
- **笔记版本冲突：** 自动保存已暂停，编辑区保留草稿。核对后使用“保留草稿并载入已保存笔记”，再从保留草稿中手动合并；不要移除版本检查或自动覆盖。
- **插件无法连接：** 先启动当前版本阅读服务，核对本机 profile 和资料库身份。不要通过切换到新空库、放宽 Origin 或覆盖旧配置消除错误。
- **ChatGPT 连接窗口不可用：** 先核对 Chromium 是否已按首次安装步骤准备；从阅读器打开“连接 ChatGPT”查看准确状态。不要接入日常 Chrome 的调试端口或把日常浏览器配置复制过来。
- **ChatGPT 需要用户处理：** 按任务说明在纸间打开的专用连接窗口完成登录、验证、模型设置或交回控制，再点击“我已完成，继续连接”。只在状态允许时恢复，不重复提交问题。
- **ChatGPT 发送结果不确定：** 先查看原会话，保留原请求及本机 journal。任务不会自动重发；重启服务或关闭窗口不能作为重试、取消的保证。
- **选文不正确：** 保存前核对预览；报告可复现页码、缩放和选区，尽量提供可共享的最小材料。
- **扫描件无法选中文字：** 使用“区域批注”框选并添加评论；这不会执行 OCR，图中文字仍不能全文检索。
- **目录无法跳页：** 核对来源是书签还是目录页识别。文字目录印刷页码未确认时，需要设置“PDF 页数减印刷页数”的偏移；无有效目标、未映射罗马页码或无文字层目录不会自动猜页。
