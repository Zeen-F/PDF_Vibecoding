# 1.1.0-beta.5：保存可靠性修复

本版修复评论草稿、批注重试、启动时服务识别和阅读位置保存问题。桌面预览版面向 Apple Silicon Mac，另提供同版本本机浏览器 ZIP；阅读、检索、笔记与批注仍保存在本机，不新增 OCR、云同步或外部问答服务。

## 四项修复

- **评论草稿恢复：** 切换笔记／批注、切文献或刷新后恢复对应评论，保留原文献、页码、引文或区域。各窗口独立保留草稿，确认本次保存成功后才清除；保存失败或冲突时保留输入供核对。恢复的评论不会自动附到新选区。
- **批注保存与重试：** 新建、编辑和删除相关数据库写入一起成功或回滚；新增批注在响应丢失后使用原 requestId 重试，避免重复新增。有效请求记录保留 30 天，容量满时拒绝新请求，不提前清除有效记录。超过期限的不确定请求应先核对已保存批注；删除结果不确定时也应重新打开文献确认。
- **启动服务识别：** 源码启动器和桌面运行时在复用本机服务前核对文献库身份、产品版本、API 版本、启动协议与健康状态。源码启动器对不兼容端口明确提示；桌面版另选空闲本机端口，不停止其他库或身份不明的服务。
- **阅读位置保存：** 快速翻页按文献合并并顺序写入；切文献及桌面正常关闭前等待最后一次保存，同一窗口的旧序号不能覆盖新页码。失败后保留恢复入口，不把未确认写入当作成功。

草稿保存在当前浏览器／桌面配置中，不能替代正式文献库备份。浏览器存储不可用、清理配置、强制退出或断电，仍可能丢失最后一次尚未提交的内容。多个窗口之间没有阅读位置全局排序，同一文献建议只在一个窗口编辑。

## 升级与回退

**升级前正常退出应用或停止服务，备份完整文献库目录。** 本版将主库从 schema 3 升级到 schema 4，增加批注请求幂等与阅读位置序号记录；已有文献、分类、笔记、批注和原始 PDF 保留。迁移在事务中完成，失败回滚，不搬迁资料，不改写 PDF。

- 桌面默认库或已记住的库在新版启动时自动迁移。
- 通过桌面菜单新选择 schema 3 旧库时，当前校验仍拒绝旧结构。先使用 beta.5 浏览器包或源码服务，将 `PAPERDESK_DATA_DIR` 指向目标库完成升级，读回并正常停止后，再从桌面菜单选择。
- 旧版不能直接打开 schema 4 库。回退 beta.4 时先停止新版，再恢复升级前完整备份；不要手工删除新增表或降低数据库版本号。

备份包括主数据库、`pdfs/` 和已有翻译数据库；运行中的 SQLite 不能只复制主文件。完整步骤见 [桌面升级说明](../desktop-release.md#从-beta4-升级)。

## 下载与运行

- 桌面版：下载 DMG，将 Paperdesk 拖入“应用程序”；无需安装 Node.js。仍未经过 Apple 开发者签名或公证，首次打开按 [安装说明](../desktop-release.md#下载与安装) 处理 macOS 提示。Intel Mac 和 Windows 桌面包不在本版范围。
- 浏览器版：下载 ZIP，使用 Node.js 24+ 执行 `npm ci --omit=dev` 和 `npm start`，打开终端显示的本机地址。文献库默认在包目录的 `data/`，也可设置 `PAPERDESK_DATA_DIR`；结束时按 Control+C。
- 下载文件分别通过 `SHA256SUMS` 和 `SHA256SUMS-browser` 核对，没有自动更新。

## 验收边界

发布检查要求对本版提交运行 `npm run check`、`npm run test:desktop` 和 `npm run test:desktop:reliability`，对打包应用再次运行两类桌面测试，并分别检查 DMG 安装副本及独立解压的浏览器 ZIP。所有测试使用隔离合成文献库，核对保存、导出、关闭／退出、重开读回和安装包内容；不使用个人文献库。

工作流配置、历史通过记录和模拟宿主结果都不能代替本版实际运行结果。远端构建是否通过以本次 GitHub Actions 为准。本轮可靠性验收不包含真实 Codex 宿主中的完整插件流程，也未完成跨窗口阅读位置全局排序；浏览器包的其他系统运行未验证。

验收完成后停止测试应用和服务，保留必要结果、日志、截图与校验值，清理解包安装副本、合成测试库及缓存；本机空间清单和恢复记录放在忽略的 `.local/`。
