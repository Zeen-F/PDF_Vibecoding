# Paperdesk 插件 0.9.0：软件内 API 翻译

在 0.8.0 文件夹、皮肤及 Work 问答基础上，按用户选择增加由纸间直接调用用户所选翻译 API 的文字选区翻译。[操作和配置](../translation.md)说明凭据开通、免费量及数据边界；[0.8.0 记录](codex-plugin-0.8.0.md)保留原验收证据。

## 改动范围

- 浏览器和原生面板增加“翻译设置”，按服务分别保存本机凭据、接口／模型参数及每月停止阈值；配置保存后启用所选服务，切换可复用既有配置。密钥不会读回到界面、对话或模型上下文。
- 预览文字选区后主动点击翻译，译文显示在独立区域，可选择中文或英文；不使用 Codex 模型额度、不自动写笔记。扫描件尚无 OCR，区域图片不能直接翻译。
- 本机服务按百度、Azure、DeepL 或自定义 OpenAI 兼容协议组装请求。认证、接口校验、字符及字节保护、串行限速、队列截止时间和保守调用量检查在服务端完成。失败不自动重试；达到本机设定阈值停止发送。同一账户在其他软件里的用量以服务商控制台为准。
- 翻译配置、用量与有界缓存使用当前库中的独立 `translation.sqlite`，主文献库 schema 3 不变。删除凭据不清空该账户的累计用量；重复选文可从本机缓存取回。
- 原生资源为 `ui://paperdesk/reader-v9.html`，共 18 个工具（8 公共、10 面板专用），新增 `paperdesk_reader_translation`。设置和译文仅在私有 `_meta` 中返回，组件不会通过消息或上下文接口把翻译内容交给模型。
- 保留既有选文字符边界、文件夹、皮肤、笔记保存与 Work 选区问答；翻译迟到响应不能替换新选区、换页或换文献后的内容。

## 本轮验证状态

- Node.js 24.19.0 下最终 `npm run check` 退出码 0：97 项 API／MCP／运行时检查全部通过，生产构建、17 项真实 DOM 选文及完整浏览器阅读流程通过。
- 翻译后端 18 项检查覆盖四种协议、认证与语言映射、独立配置、切回与重启、缓存／预算隔离、接口地址校验、密钥与错误脱敏、队列截止时间、0 上限、侧库事务迁移和失败回滚。主文献 schema 3、笔记、原 PDF 和阅读位置保持。
- 浏览器 5 组翻译流程通过：真实拖选快照、密码清空／错误保留／Tab 与 Esc、目标语言与缓存、迟到响应、四服务配置切换、自定义地址／模型、换主机密钥要求、定向清除、夜读窄窗及图片选区不发送。
- MCP 15 项协议检查通过；严格 opaque sandbox 原生面板 12 组完整回归通过，四服务的设置与译文只在私有 `_meta`，翻译不发送模型消息或上下文、不写笔记。原生测试明确控制预置配置，保留实际软件复用已存配置的行为。
- 使用原创隔离资料检查浏览器森林／夜读、Azure 译文、自定义窄窗设置及原生配置／结果。截图关闭动画后核对完整可读状态；视觉材料仅保存在本机忽略目录。
- 已安装并启用 0.9.0。安装回执对应的 7 个缓存文件与源码逐字节一致；实际缓存启动器 SDK 读回 0.9.0、18 个工具／10 个 app-only、`reader-v9` 和空 frame／resource／connect 白名单。当前服务连接原库，四服务的未配置状态可读；本轮未改变本机 profile 指向。
- 正常停止旧服务并完整备份当前库后启动新版。三份 PDF 哈希及五张主库表读回一致，schema 3、完整性和外键检查通过。正式库只做备份与读回，不用于测试，未配置密钥、不发送文献到外部服务。
- 真正的服务商连接、账户额度与翻译质量仍需用户填写有效凭据后验证；实际 Codex 宿主交互仍需重新打开新版面板验收。模拟测试与安装读回不能替代这两项。
- 使用独立功能分支与草稿 PR 保留可审查变更；远端 CI 以该提交的 GitHub Checks 结果为准，不将本机通过当作远端通过。
