# Paperdesk 插件 0.2.0 打开流程修复

2026-10-05，修复原生面板内嵌本机网页被屏蔽的问题。

## 改动

原生资源改为 `ui://paperdesk/reader-v2.html`。组件直接显示文献、单页 PNG、目录和单一笔记区，移除嵌套 iframe 和组件内 localhost 请求；HTTP Origin 保护保持严格。面板专用工具把展示数据放在私密 `_meta`，只有用户确认预览才共享选区。

PDF 在本机独立子进程按页渲染，限制输出像素、并发和等待时间，不增加文件字节大小上限。笔记手动保存使用版本校验，冲突时保留草稿并提供核对与手动合并入口。

## 本次验证

- Node.js 24.19.0 `npm run check` 通过：70 项 API/MCP/runtime/render 测试、生产构建、17 项真实 DOM 选文回归及完整浏览器阅读流程。
- 禁止网络访问的 opaque sandbox 中，以真实 SDK stdio 工具完成打开、翻页、目录、笔记、正反区域预览、明确共享与延迟取消；展示数据没有进入模型可见字段。新增默认空参数只列元数据、CAS 冲突核对/合并与能力降级回归也通过。
- 本机安装回读为 0.2.0 installed/enabled，缓存 7 个文件与源码一致。缓存启动器发现 8 个公共工具及 6 个 app-only 工具，读取到新的 UI 资源。
- 对已有 749 页扫描书的当前页，通过安装后的 MCP 工具获得实际 1200×1698 PNG，图片内容可见，原生显示图片只在 `_meta` 返回。测试没有向正式笔记写入内容。
- 3 篇正式文献的原 PDF 字节、笔记和批注前后相同。验收期间一本书的保存阅读位置从 333 变为 334，未自动回退；单页渲染接口本身不回写阅读位置，其只读行为另有隔离测试。
- 本机阅读服务已重启为新版本；已有浏览器阅读页可见当前 PDF 和笔记区。

## 尚待真实宿主确认

浏览器沙盒模拟不能证明 Codex 原生宿主已加载新工具、保留 `_meta` 或接受模型上下文。自动化可检查已有浏览器阅读页，但当前任务没有可控制的原生 MCP Apps 面板。需关闭旧面板，在启用更新插件的新会话中重新打开，并以实际显示结果确认。

原生面板没有导入、完整批注编辑、目录页码校正、OCR 或云服务；这些已有阅读操作可在浏览器版完成。笔记需手动保存，关闭面板可能丢失未保存草稿。
