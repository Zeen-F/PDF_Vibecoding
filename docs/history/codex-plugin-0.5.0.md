# Paperdesk 插件 0.5.0：自动连接普通 ChatGPT

2026-10-07，自动任务接入浏览器阅读器与原生组件。用户在预览中确认问题和选区后，由本机 EGO Lite 使用普通 ChatGPT；本记录分别保留实现、隔离检查与真实账号操作的证据。

## 改动范围

- 默认动作“向 ChatGPT 提问”冻结用户问题、文献、PDF 页码与文字／区域 PNG。程序连接、核对 Chat／Latest／Extra High（xhigh）、上传必要图片、单次发送、等待回答并回传；无法核实模式或模型时暂停，不降级。
- 当前提问预览保持打开时，直接显示完整只读“ChatGPT 回答预览”，无需额外点击；关闭或翻页后不强开。“查看回答”保留为回看来源、问题、进度与复制回答的入口，不自动写笔记。原有 Codex 讨论与“手动备用方式”继续保留。
- 本机新增提交、查询、明确恢复任务的 API；插件使用 `reader-v5`、17 个工具（9 个 app-only），其中 3 个自动任务工具结果只进入 `_meta.chatgptJob`。不调用 `ui/message` 或 Codex 模型，不使用 API 密钥或 ChatGPT 私有 HTTP 接口。
- 一个任务执行器串行运行，同 UUID／同输入幂等；`needs_user` 与 `uncertain` 暂停队列，未确认发送不自动重试。journal 持久化最多 8 份完整任务，淘汰后保留轻量请求凭据；重启不重新发送。
- 输入、回答、journal、执行 ledger 与 PNG 保存在文献库 `chatgpt-jobs/`，目录权限 0700，journal、输入与执行 ledger 为 0600，上传用 PNG 快照为只读 0400，属于不入 Git 的个人资料。原 PDF、笔记及数据库 schema 不变。

开发验证发现并修复了页面加载期间发送按钮尚未启用，以及重复准备只读 PNG 快照时的复用问题。最终隔离流程复用了原先尚未发送的测试页，保护检查通过后才单次提交；没有将受阻尝试计作成功发送。

自动检查使用原创材料、隔离文献库与替代执行器，不向真实 ChatGPT 发问。真实操作的输入、页面和本机执行材料不得进入仓库；每次最终验收应区分发送、收到页面回答、程序取回及 UI 显示。

## 当前限制

需要用户已安装启动 EGO Lite，并能登录 ChatGPT；登录、验证码和用户控制由用户处理。只有 `needs_user` 且允许恢复时，点击“我已完成，继续连接”才继续；`uncertain` 不自动重发。

当前提问预览保持打开时直接显示完整回答；关闭预览或翻页后不强开，当前 UI 实例仍可通过“查看回答”返回原任务。网页／原生面板实例结束后，任务显示列表暂不自动恢复。关闭预览或面板不取消已经启动的执行。服务关闭会记录关闭标记，执行器在每次后续变更操作前检查它；这不是任务取消接口，不能保证终止已经在途的操作，已发出的问题也不会被撤回。不要通过删除 journal、ledger 或请求凭据强行重试。
