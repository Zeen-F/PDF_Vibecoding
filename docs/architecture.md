# 架构与数据流

应用由一个 React 界面、一个 Express 本地服务和一个 SQLite 文献库组成。生产模式由本地服务同时提供构建后的界面与 API；开发模式由 Vite 提供界面，并代理 API 到独立开发服务。

```text
浏览器
  ├─ React：文献列表、阅读、批注、笔记
  ├─ PDF.js：PDF 画布与文字层
  └─ 同源 /api 请求
          ↓
Express 本地服务（127.0.0.1）
  ├─ PDF 解析、输入校验、搜索、导出
  ├─ SQLite：documents / pages / annotations
  └─ pdfs/：未改写的原始 PDF
```

## 主要流程

**导入：** 文件流式写入本机文献库的 `pdfs/.incoming/` 随机临时文件 → 进入当前服务的串行导入队列 → 检查格式并流式计算 SHA-256 查重 → PDF.js 提取元信息及逐页文字 → 移动原始 PDF 并提交数据库记录。相同内容返回已有文献，不因文件名不同重复保存；完成或失败后清理临时输入。

上传不设固定文件字节上限。临时落盘避免上传阶段将整个文件留在请求内存中，解析串行避免多个大 PDF 同时解析；这些措施不代表无限容量或恒定内存。仍保留页数和提取字符限制，PDF.js 的内部缓存、渲染与文献库也依赖实际可用的内存和磁盘。

**阅读与批注：** 浏览器请求原始 PDF → PDF.js 渲染画布和文字层 → 依据位置整理文字节点顺序 → 读取真实字符选区和矩形 → 用户核对引文并保存。批注矩形使用含 PDF 固有旋转的默认视口坐标，按页面宽高归一化到 0–1；缩放时据此重新展示。

**区域批注：** 在区域模式中接收指针拖拽 → 将正反向框选转换为页面内的一个归一化矩形 → 从本地画布生成临时预览 → 用户确认并保存 `kind: region`、空引文、评论和坐标。批注保存 API 不接收预览，数据库不存图片；图片文字不经过 OCR，也不会进入全文索引。用户另行点击“交给 Codex”时，预览可进入短期阅读会话。保存后的区域沿用批注的页码导航和搜索评论流程。

**笔记与导出：** 用户编辑 → 浏览器暂存草稿 → 延时触发顺序保存队列 → 服务端写入数据库 → 界面显示成功。导出先等待当前笔记保存，再由服务生成 Markdown。浏览器草稿不是正式数据库的副本。

界面只有一个笔记编辑区。旧的 `notesZh`、`notesEn` 存储字段继续兼容：前后端使用同一合并函数，以空行、Markdown 分隔线和空行连接两段非空内容。只读打开、无变化保存及导出保持原字段；真实编辑保存后将完整内容写入 `notesZh`，清空 `notesEn`。旧双字段浏览器草稿也按此规则恢复，不会要求用户重写或丢弃其中一段。笔记合并规则不需要结构变更；0.8.0 另为文献分类和库偏好迁移到 schema 3。

**搜索：** 服务端读取文献标题、页面文本、笔记和批注，规范化换行与空白后进行文本子串匹配，最多返回 100 条。旧笔记两个存储字段中的内容都参与检索；界面根据来源跳页、标亮正文或打开对应面板。当前未使用全文搜索索引或语义向量。

**Codex 接入：** 安装缓存中的启动器读取仓库外的本机配置 → 从固定工作区加载 MCP bridge → 核对 loopback 服务和资料库身份 → 提供明确文献的单页文字、已共享选区和笔记工具。打开阅读页不自动读取全文或截图；文字/区域只在用户共享后进入临时会话，工具请求的内容可进入当前 Codex 模型上下文。

每个阅读窗口独立标识，服务器不在多个活动窗口间猜测。页面隐藏或会话过期后不能当作当前上下文。浏览器笔记保存和插件追加都比较 raw 笔记版本；插件追加还检查活跃未保存草稿。发生冲突时保留草稿并暂停自动保存，明确恢复后继续。幂等追加仅覆盖本次服务运行中的 10 分钟，不能把重启后的不明结果视为安全重试。

MCP Apps 资源是自含阅读组件，通过宿主父窗口的 JSON-RPC 请求面板专用工具，使用 `_meta` 中的单页 PNG、文字、目录和笔记绘制界面。组件没有嵌套网页，也不直接请求本机服务或外部资产；普通阅读数据不会自动进入模型上下文。用户确认共享或发问时，再按宿主能力传递对应文字／图片。来源校验和本机 API 校验各自保留。

0.7.0 恢复的问答只进入当前 Work／Codex 对话。“交给 Codex”更新共享上下文；解释、提炼要点及自定义问题通过 `ui/message` 发送当次选区快照，回答不会自动写笔记。协议测试不替代恢复后当前客户端的实际验收。普通 loopback 阅读页与 stdio 文献工具仍可独立使用，具体安装和证据边界见 [Codex 插件](codex-plugin.md)。

**分类与皮肤：** 本机库返回单层文件夹、数量和皮肤偏好 → 界面筛选元数据 → 用户拖动或通过“移动到”提交所属分类。文献只有一个可空的文件夹归属，删除文件夹时回到未分类；文件位置与正文不变。组织操作不重新加载当前页面或笔记；原生面板先读完有界分页再筛选，防止遗漏后续页文献。主题只设置界面颜色变量，不处理或变色 PDF 页图。原生通过 3 个 app-only 工具读写，结果在 `_meta.library`，不触发模型消息或上下文共享。

**目录：** 用户展开目录 → 请求文献的 `/toc` → 本机 PDF.js 优先解析书签与目标页 → 没有书签时检查前 40 页的文字目录 → 返回层级条目和经验证的 PDF 页码。文字目录的印刷页码必须经页码标签或多个标题位置校正；无法验证时不提供猜测跳转。用户可在当前浏览器为该文献保存数字页码偏移，目录筛选与展开由界面处理，跳页沿用现有阅读位置保存流程。

## 数据与边界

`documents` 存储文献标识、内容哈希、元信息、笔记、阅读页码及可空的 `folder_id`；`pages` 存储每页提取文字；`annotations` 存储批注类型、引文、评论、颜色与归一化矩形。schema 3 新增 `folders` 和单行 `library_preferences`（`id=1`、`theme`）；`folder_id` 外键在文件夹删除时置空，旧文献默认未分类，主题默认 `forest`。SQLite 使用 WAL，结构和版本在同一事务提交；失败回滚，并拒绝打开更高版本数据库。既有笔记原始字段、批注、阅读位置及原 PDF 保留。升级前完整备份，回退时恢复升级前完整库。

文献栏展开状态保存在当前浏览器本地存储中；收起时界面保留其 DOM 并隐藏，快捷键可重新展开搜索。布局偏好不改变文献、阅读页码或已保存批注坐标。

目录结果只缓存在服务进程内存中，重启后按需重新提取；现有文献无需重新导入，也不新增数据库字段。手动目录偏移属于浏览器偏好，不包含在数据库备份或 Markdown 笔记导出中。原始 PDF 始终不变。

前端加载的 worker、CMap、标准字体与 WASM 随本机构建准备。服务只监听回环地址，并校验 Host／Origin；这个设计面向单机使用，没有账户系统和多用户权限模型。详细请求契约见 [API.md](../API.md)。

**独立翻译：** 用户配置本机凭据 → 明确点击文字选区翻译 → 本机检查参数、缓存和字符上限 → 所选服务适配器与校验后的接口地址 → 译文只返回当前阅读器。原生面板用 app-only 工具获得私有 `_meta`，不调用消息或模型上下文接口。翻译配置、累计用量和缓存位于独立 `translation.sqlite`，不修改文献主库 schema；凭据和译文不纳入 Git。四种适配器为百度、Azure、DeepL 和自定义 OpenAI 兼容接口；各服务配置分别保存，修改主机时不能自动转发旧密钥。请求预算在发送前保守计入，失败不自动重试；本机计数不包含同一账户在其他工具里的用量。
