# 架构与数据流

应用由一个 React 界面、一个 Express 本地服务和一个 SQLite 文献库组成。生产模式由本地服务同时提供构建后的界面与 API；开发模式由 Vite 提供界面，并代理 API 到独立开发服务。

```text
浏览器
  ├─ React：文献列表、阅读、批注、笔记
  ├─ PDF.js：PDF 画布与文字层
  └─ 同源 /api 请求
          ↓
Express 本地服务（127.0.0.1）
  ├─ PDF 解析、输入校验、搜索、导出
  ├─ SQLite：documents / pages / annotations
  └─ pdfs/：未改写的原始 PDF
```

| `src/Notes.jsx` | 双语编辑、草稿恢复、自动保存队列和导出前保存 |

## 主要流程

**导入：** 文件流式写入本机文献库的 `pdfs/.incoming/` 随机临时文件 → 进入当前服务的串行导入队列 → 检查格式并流式计算 SHA-256 查重 → PDF.js 提取元信息及逐页文字 → 移动原始 PDF 并提交数据库记录。相同内容返回已有文献，不因文件名不同重复保存；完成或失败后清理临时输入。

上传不设固定文件字节上限。临时落盘避免上传阶段将整个文件留在请求内存中，解析串行避免多个大 PDF 同时解析；这些措施不代表无限容量或恒定内存。仍保留页数和提取字符限制，PDF.js 的内部缓存、渲染与文献库也依赖实际可用的内存和磁盘。

**阅读与批注：** 浏览器请求原始 PDF → PDF.js 渲染画布和文字层 → 依据位置整理文字节点顺序 → 读取真实字符选区和矩形 → 用户核对引文并保存。批注矩形使用含 PDF 固有旋转的默认视口坐标，按页面宽高归一化到 0–1；缩放时据此重新展示。

**区域批注：** 在区域模式中接收指针拖拽 → 将正反向框选转换为页面内的一个归一化矩形 → 从本地画布生成临时预览 → 用户确认并保存 `kind: region`、空引文、评论和坐标。预览不进入 API 或数据库；图片文字不经过 OCR，也不会进入全文索引。保存后的区域沿用批注的页码导航和搜索评论流程。

**笔记与导出：** 用户编辑 → 浏览器暂存草稿 → 延时触发顺序保存队列 → 服务端写入数据库 → 界面显示成功。导出先等待当前笔记保存，再由服务生成 Markdown。浏览器草稿不是正式数据库的副本。

**搜索：** 服务端读取文献标题、页面文本、双语笔记和批注，规范化换行与空白后进行文本子串匹配，最多返回 100 条。界面根据来源跳页、标亮正文或打开对应面板。当前未使用全文搜索索引或语义向量。

**目录：** 用户展开目录 → 请求文献的 `/toc` → 本机 PDF.js 优先解析书签与目标页 → 没有书签时检查前 40 页的文字目录 → 返回层级条目和经验证的 PDF 页码。文字目录的印刷页码必须经页码标签或多个标题位置校正；无法验证时不提供猜测跳转。用户可在当前浏览器为该文献保存数字页码偏移，目录筛选与展开由界面处理，跳页沿用现有阅读位置保存流程。

## 数据与边界

`documents` 存储文献标识、内容哈希、元信息、笔记和阅读页码；`pages` 存储每页提取文字；`annotations` 存储批注类型、引文、评论、颜色与归一化矩形。SQLite 使用 WAL；schema 2 以事务为旧记录增加默认 `text` 类型，保留既有内容，失败回滚，并拒绝打开更高版本数据库。升级前备份与回退恢复由文献库使用者执行。

文献栏展开状态保存在当前浏览器本地存储中；收起时界面保留其 DOM 并隐藏，快捷键可重新展开搜索。布局偏好不改变文献、阅读页码或已保存批注坐标。

目录结果只缓存在服务进程内存中，重启后按需重新提取；现有文献无需重新导入，也不新增数据库字段。手动目录偏移属于浏览器偏好，不包含在数据库备份或 Markdown 笔记导出中。原始 PDF 始终不变。

前端加载的 worker、CMap、标准字体与 WASM 随本机构建准备。服务只监听回环地址，并校验 Host／Origin；这个设计面向单机使用，没有账户系统和多用户权限模型。详细请求契约见 [API.md](../API.md)。
