# 项目背景与已确认需求

纸间 Paperdesk 从一次本地 PDF 工作台原型开发继续演进。`PDF_Vibecoding` 是后续维护的项目工作区；产品名仍为“纸间 Paperdesk”。迁移的目标是让已有源码、数据和开发上下文可继续使用，并建立可复现的开发、检查和审查流程。

## 已确认的产品选择

| 选择 | 对实现的约束 |
| --- | --- |
| Mac 本地网页应用 | 浏览器访问本机服务；保留 Mac 启动器 |
| 文字高亮和评论 | 使用 PDF 文字层与页面坐标；原始 PDF 不改写 |
| 单层文献分类 | 新建、重命名和删除文件夹；拖动或选择移动；删除分类保留其中的文献 |
| 四套阅读皮肤 | 森林、暖砂、雾蓝、夜读；偏好保存在本机库，PDF 原色不变 |
| 单一笔记区 | 一个编辑区自由记录，不按语言分栏；旧内容完整兼容 |
| 本机文献库 | PDF、索引、笔记、批注留在本机；普通阅读无外部服务依赖，用户交给 Codex 的内容可进入模型请求 |
| 可安装 Codex 插件 | 复用现有文献库；用户预览并确认后共享选区或向当前对话提问，明确要求后才追加到单一笔记区 |
| 软件直接调用翻译 API | 用户在本机设置服务／接口参数／密钥，点击后发送文字选区；译文在阅读器内显示，不自动写笔记 |
| 当前 Work／Codex 对话问答 | 0.7.0 恢复为唯一阅读问答路径；问题与确认的选区快照发送到当前对话 |
| 持续维护的开发工作区 | 版本控制、锁定依赖、隔离开发数据、自动检查及 PR 流程 |

## 已有功能

PDF 导入与内容去重、单层文件夹、拖动／键盘移动、四套阅读皮肤、可收起的文献栏、正文／笔记／批注搜索、分页阅读和缩放、可折叠的章节目录与标题筛选、文字高亮和区域框选评论、阅读位置恢复、笔记自动保存、Markdown 导出。随项目提供一份原创阅读示例。

区域批注为无文字层扫描件及图表提供位置标记，不做 OCR、不产生虚构引文。区域以单个归一化矩形和用户评论存储，临时画布预览不保存；评论可搜索，Markdown 导出保留页码与坐标。schema 2 迁移保留旧文字批注。文献栏收起状态仅在当前浏览器持久化，搜索快捷键自动展开它。

笔记保存使用队列处理请求顺序，导出前等待当前笔记保存完成；浏览器草稿用于失败恢复。引用和批注与原文件分开保存，已有引文不会因选文算法更新自动改写。

当前采用单一笔记区。旧版两个笔记字段在显示和导出时保留内容并以分隔线连接；仅阅读或导出不改写它们，实际编辑后才统一保存。现有浏览器草稿也要完整恢复；当时的笔记界面调整不改变数据库结构；0.8.0 的分类功能另行升级到 schema 3。

章节目录优先读取 PDF 内置书签，没有书签时只尝试识别前 40 页中的文字目录页。旧文献按需提取，无需重新导入、不改数据库结构。印刷页码须经标签或多个章节位置验证，无法确认时由用户设置数字页码偏移；校正仅保存在当前浏览器，不改 PDF。没有文字层的扫描目录不进行 OCR，复杂目录识别和未知目标不承诺可跳转。

PDF 导入不设固定文件字节上限；仍保留 2,000 页及 2,000 万提取字符的处理保护。超大或复杂文档能否处理取决于本机磁盘、内存及 PDF.js 能力，不能把移除固定大小限制理解为无限资源承诺。

插件原型使用本机 MCP stdio 桥接，不直接访问任意文件、不引入独立文献库或模型 API 密钥。阅读器明确共享文字或扫描区域，多个窗口须指定会话；本机共享会话只存在短期内存，不改变批注；已经发送到对话的内容会保留在对话记录中。笔记新增版本校验、追加幂等保护和冲突草稿恢复，保留旧内容；这些笔记保护与 0.8.0 的 schema 3 分类迁移相互独立。0.2.0 原生面板改为直接组件绘制，app-only 工具的 `_meta` 返回单页 PNG 和展示数据，移除 localhost iframe。用户已于 2026-10-06 确认面板在 Codex 中可以打开；这项确认不等于所有上下文或消息能力均已验收。

0.3.0 增加用户主动发起的选区讨论：预览中选择解释、提炼要点或自定义提问，将问题和当次选区快照发送到当前 Codex 对话，避免回答依赖随后可能变动或过期的阅读会话。原有“交给 Codex”只共享，不触发回答。宿主消息或图片能力不足时提供可复制提问与普通工具读取说明，不声称图片已经发送。

0.7.0 按用户明确选择恢复上述 0.3.0 功能，以当前 Work／Codex 对话为唯一阅读问答路径。普通 ChatGPT 网页连接及自动提问实验不再属于当前产品流程；本次恢复不新增问答服务或登录步骤。

0.8.0 增加单层文件夹、文献拖动／键盘移动与森林、暖砂、雾蓝、夜读四套皮肤。分类与主题是本机库偏好，不会自动向模型发送文献内容；筛选和移动不得重新加载当前页、覆盖笔记草稿或改变选区问答目标。删除文件夹使文献回到未分类，不删除资料。schema 3 迁移前须完整备份，默认旧文献未分类、主题森林；旧 PDF、笔记、批注与阅读位置保留。

聊天回答不自动写入笔记。只有明确要求记录时才调用追加工具；原生笔记区可主动刷新，或在收到当前文献的追加结果后安全刷新。任何刷新都必须保护未保存草稿及正在保存的内容，不能替换用户正在编辑的文本。当前实现、自动测试与真实宿主效果分别记录，验证状态见 [0.9.0 变更记录](history/codex-plugin-0.9.0.md)；[0.7.0 恢复记录](history/codex-plugin-0.7.0.md) 和 [0.3.0 变更记录](history/codex-plugin-0.3.0.md) 作为历史证据保留。

## 必须继承的修复

1.0.1 处理了 PDF 内容流顺序与视觉阅读顺序不一致时的选文问题：页脚曾被夹入标题间的引文。文字层现在依据几何位置组织阅读顺序，再按真实字符选区提取引文。

相关行为包括反向拖选、跨行、中文与英文、混合字体、常见上下标、双栏及通栏标题／页脚；取消选区后清除旧引文；适配特殊页面单位以保持画布与文字层对齐；批注弹窗打开期间锁定引用，避免布局变化改写待保存内容。

这些修复针对已覆盖场景，不代表所有 PDF 都正确。复杂绕排、竖排、从右向左文本、异常编码与扫描件仍有明确限制；完整范围见 README。

## 迁移与证据

已有源码和本地文献库已迁入本工作区，原始来源保留。个人来源路径、对话定位、文件清单、校验和及数据备份记录位于本机 `.local/`，不提交到仓库。

[历史验收摘要](history/1.0.1.md) 记录此前报告的结果；迁移后的复验应单独说明运行环境、命令与实际结果。历史通过数不能用来证明当前分支已通过检查。

## 未决定或未实现的范围

0.9.0 按用户选择增加软件自身直接调用用户所选翻译 API 的文本选区翻译。APPID 与密钥在本机设置，译文在阅读器内显示，不使用 Codex 模型、不自动写笔记；只在用户点击时发送所选文字。主文献库 schema 3 不变，翻译配置、用量与缓存单独存储。详见 [软件内翻译](translation.md)。OCR、云同步、多人协作、PDF 内嵌批注编辑、大规模检索优化和跨平台安装包均不是本轮交付承诺。可选 Codex 辅助按上述插件边界实现；原生面板打开和 0.3.0 发送问题后收到回答曾获用户确认，0.8.0 分类和皮肤的实际客户端流程仍需单独验收。不同宿主及消息类型按各自能力验证。尚未选择开源许可证。后续候选事项见 [roadmap.md](roadmap.md)。
