# 项目背景与已确认需求

纸间 Paperdesk 从一次本地 PDF 工作台原型开发继续演进。`PDF_Vibecoding` 是后续维护的项目工作区；产品名仍为“纸间 Paperdesk”。迁移的目标是让已有源码、数据和开发上下文可继续使用，并建立可复现的开发、检查和审查流程。

## 已确认的产品选择

| 选择 | 对实现的约束 |
| --- | --- |
| Mac 本地网页应用 | 浏览器访问本机服务；保留 Mac 启动器 |
| 文字高亮和评论 | 使用 PDF 文字层与页面坐标；原始 PDF 不改写 |
| 单一笔记区 | 一个编辑区自由记录，不按语言分栏；旧内容完整兼容 |
| 本机文献库 | PDF、索引、笔记、批注留在本机；普通阅读无外部服务依赖，用户主动发送的选区进入相应 AI 对话 |
| 可安装 Codex 插件 | 复用现有文献库；用户预览并确认后共享选区或向当前对话提问，明确要求后才追加到单一笔记区 |
| 普通 ChatGPT 阅读讨论 | 用户确认问题和选区后，纸间管理的专用浏览器连接普通 ChatGPT、单次发送并取回回答；登录／验证由用户处理，不替换成 Codex 回答 |
| 持续维护的开发工作区 | 版本控制、锁定依赖、隔离开发数据、自动检查及 PR 流程 |

## 已有功能

PDF 导入与内容去重、可收起的文献栏、正文／笔记／批注搜索、分页阅读和缩放、可折叠的章节目录与标题筛选、文字高亮和区域框选评论、阅读位置恢复、笔记自动保存、Markdown 导出。随项目提供一份原创阅读示例。

区域批注为无文字层扫描件及图表提供位置标记，不做 OCR、不产生虚构引文。区域以单个归一化矩形和用户评论存储，临时画布预览不保存；评论可搜索，Markdown 导出保留页码与坐标。schema 2 迁移保留旧文字批注。文献栏收起状态仅在当前浏览器持久化，搜索快捷键自动展开它。

笔记保存使用队列处理请求顺序，导出前等待当前笔记保存完成；浏览器草稿用于失败恢复。引用和批注与原文件分开保存，已有引文不会因选文算法更新自动改写。

当前采用单一笔记区。旧版两个笔记字段在显示和导出时保留内容并以分隔线连接；仅阅读或导出不改写它们，实际编辑后才统一保存。现有浏览器草稿也要完整恢复；这次界面调整不更改 schema 2。

章节目录优先读取 PDF 内置书签，没有书签时只尝试识别前 40 页中的文字目录页。旧文献按需提取，无需重新导入、不改数据库结构。印刷页码须经标签或多个章节位置验证，无法确认时由用户设置数字页码偏移；校正仅保存在当前浏览器，不改 PDF。没有文字层的扫描目录不进行 OCR，复杂目录识别和未知目标不承诺可跳转。

PDF 导入不设固定文件字节上限；仍保留 2,000 页及 2,000 万提取字符的处理保护。超大或复杂文档能否处理取决于本机磁盘、内存及 PDF.js 能力，不能把移除固定大小限制理解为无限资源承诺。

插件原型使用本机 MCP stdio 桥接，不直接访问任意文件、不引入独立文献库或模型 API 密钥。阅读器明确共享文字或扫描区域，多个窗口须指定会话；本机共享会话只存在短期内存，不改变批注；已经发送到对话的内容会保留在对话记录中。笔记新增版本校验、追加幂等保护和冲突草稿恢复，保持旧内容与 schema 2。0.2.0 原生面板改为直接组件绘制，app-only 工具的 `_meta` 返回单页 PNG 和展示数据，移除 localhost iframe。用户已于 2026-10-06 确认面板在 Codex 中可以打开；这项确认不等于所有上下文或消息能力均已验收。

0.3.0 增加用户主动发起的选区讨论：预览中选择解释、提炼要点或自定义提问，将问题和当次选区快照发送到当前 Codex 对话，避免回答依赖随后可能变动或过期的阅读会话。原有“交给 Codex”只共享，不触发回答。宿主消息或图片能力不足时提供可复制提问与普通工具读取说明，不声称图片已经发送。

用户已确认 0.3.0 在实际 Codex 客户端能发出问题并收到回答；没有据此认定所有宿主及文字／图片类型均完成人工验收，证据见 [0.3.0 变更记录](history/codex-plugin-0.3.0.md)。

0.4.0 增加独立的“交给 ChatGPT”准备入口，满足阅读讨论交给普通 ChatGPT 的选择。原生面板与浏览器都准备用户问题、文献标题、PDF 页码及选中文字；扫描区域仅导出已预览的精确 PNG。问题不包含内部文献／会话标识、本机工具操作指令、笔记或未选择的页面内容。入口不调用 `ui/message`、上下文注入或模型请求，只打开固定 `https://chatgpt.com/`，不拼接提问参数、不自动上传或发送。用户自行确认普通 Chat 模式、粘贴问题并附图；原生宿主不支持或拒绝下载时，在浏览器同页重新框选导出。

0.5.0 在上述入口增加自动任务：点击“向 ChatGPT 提问”时冻结问题与选区，通过本机任务 API 和 EGO Lite 的真实浏览器界面连接普通 ChatGPT、上传必要区域 PNG、发送一次、等待并取回回答。依赖用户已安装启动的 EGO Lite 与 ChatGPT 登录状态；必须核对 Chat、Latest、Extra High（xhigh），无法核实时暂停，不退回其他模式或模型。无需 `ui/message`、Codex 模型、模型 API 密钥或 ChatGPT 私有 HTTP 接口。旧手动流程保留在“手动备用方式”。

0.6.0 去除默认独立 EGO 依赖，纸间按需管理专用 Chromium 与 `~/.config/paperdesk/chatgpt-browser/` 登录配置，既不借用日常 Chrome／EGO 配置，也不将登录资料混入文献库。“连接 ChatGPT”提供状态、打开窗口和关闭连接；`ready` 只说明窗口可用。首次登录或验证在专用窗口完成后，回纸间明确继续任务；默认连接失败不会自动退回 EGO。明确设置 `PAPERDESK_CHATGPT_ENGINE=ego` 才可选择旧执行器。

原生选区预览默认使用 ChatGPT 的解释、提炼和自定义问题预设，预设只填问题，确认后才发送；Codex 讨论和共享收在默认折叠的可选区。已完成回答可以继续提问：新请求沿用原文献／页码／选区，并由服务端加入先前问答，在新的专用页提交。它不是原 ChatGPT 网页会话的连续发送，客户端不能提供任意旧答案；结果仍只读、不自动写笔记。

任务按请求 UUID 与完整输入校验幂等，单个执行器串行运行。`needs_user` 等待用户处理后明确继续；`uncertain` 不自动重发，并暂停后续执行。本机持久化日志最多保存 8 份完整任务，淘汰后继续保留轻量请求凭据；服务重启将未确认状态保守处理，不重新发送。输入、回答、执行 ledger 与 PNG 保存在文献库 `chatgpt-jobs/`，目录权限为 0700，journal、输入与执行 ledger 为 0600，上传用 PNG 快照为只读 0400；不提交 Git，不修改 PDF、笔记或 schema 2。

当前提问预览保持打开时，任务完成后直接显示完整只读“ChatGPT 回答预览”。关闭预览或翻页不会重新弹出回答，仍可通过“查看回答”回看当前文献的原任务或复制回答；关闭预览不取消已启动执行。执行中“关闭连接”被拒绝；服务停止会关闭专用浏览器并保守保留未确认任务，但已发送问题无法撤回。当前网页／原生面板实例结束后，任务显示列表暂不自动恢复。回答不直接写笔记；Codex 对话中只有明确要求记录时才调用追加工具，已有刷新与草稿保护保持不变。

ChatGPT Work 与 Codex 共享用量，普通 Chat 也受套餐与模型限制；自动连接不改变账号计费规则。[官方模式说明](https://learn.chatgpt.com/docs/use-chatgpt) · [官方用量说明](https://learn.chatgpt.com/docs/pricing)。0.5.0 已分别验证原创文字／图片的真实单次发送与自动取回，以及隔离本机 API 经默认 EGO 执行器回传任务回答的完整流程。两端内联显示由自动回归验证；完整检查、安装与 CI 保持分别记录，这些证据属于 [0.5.0 记录](history/codex-plugin-0.5.0.md)，不代替专用浏览器和追问的本轮验收；当前状态见 [0.6.0 记录](history/codex-plugin-0.6.0.md)。

## 必须继承的修复

1.0.1 处理了 PDF 内容流顺序与视觉阅读顺序不一致时的选文问题：页脚曾被夹入标题间的引文。文字层现在依据几何位置组织阅读顺序，再按真实字符选区提取引文。

相关行为包括反向拖选、跨行、中文与英文、混合字体、常见上下标、双栏及通栏标题／页脚；取消选区后清除旧引文；适配特殊页面单位以保持画布与文字层对齐；批注弹窗打开期间锁定引用，避免布局变化改写待保存内容。

这些修复针对已覆盖场景，不代表所有 PDF 都正确。复杂绕排、竖排、从右向左文本、异常编码与扫描件仍有明确限制；完整范围见 README。

## 迁移与证据

已有源码和本地文献库已迁入本工作区，原始来源保留。个人来源路径、对话定位、文件清单、校验和及数据备份记录位于本机 `.local/`，不提交到仓库。

[历史验收摘要](history/1.0.1.md) 记录此前报告的结果；迁移后的复验应单独说明运行环境、命令与实际结果。历史通过数不能用来证明当前分支已通过检查。

## 未决定或未实现的范围

OCR、自动翻译、云同步、多人协作、PDF 内嵌批注编辑、大规模检索优化和跨平台安装包均不是此次工程迁移的交付承诺。可选 Codex 辅助及普通 ChatGPT 自动任务按上述边界实现；原生面板打开和 0.3.0 对话回答的真实流程已由用户确认，0.5.0 的真实自动取回、区域 PNG 上传与两端内联显示已有各自证据，0.6.0 专用连接、追问及当前安装／宿主状态仍按版本记录单独核验。尚未选择开源许可证。后续候选事项见 [roadmap.md](roadmap.md)。
