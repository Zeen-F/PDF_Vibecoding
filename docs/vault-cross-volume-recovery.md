# 跨盘保存与桌面成品验证

Obsidian 库和本机索引可以位于不同磁盘。替换已有 Markdown 前，Paperdesk 优先在配置的库外恢复目录建立硬链接；仅当系统明确返回 `EXDEV`（跨卷）时，才使用回退路径。

回退在原 Markdown 同目录保留一个隐藏的 `.*.paperdesk-recovery` 硬链接，并在库外恢复目录创建、刷盘、核对和发布一份完整快照。同目录链接保留原文件 inode，替换前后的并发检查和冲突恢复仍使用它，外部编辑器通过旧句柄完成的晚到写入也不会丢失。替换仍通过同目录临时文件的原子重命名完成；不能退化为先删除正式笔记再复制。内部保留链接不以 `.md` 结尾，不会被当成新的 Paperdesk 笔记索引。

这些保留链接和原有恢复副本一样不会在保存成功后自动删除。权限拒绝、恢复目录被占用、复制或刷盘失败仍使保存失败，原文件保持不变；不会更改磁盘权限、绕过恢复步骤或把未保存内容标为已保存。

单元测试覆盖跨卷模拟、重开位置、原 inode 的晚到写入、替换时并发编辑，以及权限/复制/刷盘失败。真实跨卷 API 回归通过 `PAPERDESK_TEST_VAULT_PARENT` 指定**专门的合成测试目录**，其磁盘必须与系统临时目录不同。测试会先验证原生 `EXDEV`，再检查失败保护、保存重试、笔记保存及删除测试索引后的重启重建；不使用真实知识库。未提供该变量时，该项明确跳过。

```powershell
$env:PAPERDESK_TEST_VAULT_PARENT='D:\Paperdesk-synthetic-tests'
node --test tests/vault-cross-volume.test.mjs
```

桌面打包要求真实物理 `node_modules`，不能通过 Junction/符号链接复用另一个工作区。预检运行 npm 的生产依赖图检查；打包后递归检查成品内所需依赖，不允许回退到源码祖先目录，并检查内嵌 Paperdesk 面板和启动器存在。`plugins/paperdesk` 是成品的一部分，不应在安装后再手工补文件。成品还须在源仓库之外运行桌面回归；打包命令退出 0 本身不能代替运行验收。
