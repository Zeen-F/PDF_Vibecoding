# 纸间 Codex 插件

插件通过本机 HTTP API 连接已有纸间工作区，MCP 使用官方 SDK 的 stdio 传输。它不直接打开 SQLite，不复制个人文献到插件缓存，也不把本机阅读器发布到公网。0.6.0 默认使用纸间管理的专用浏览器连接普通 ChatGPT 并取回回答；当前 Codex 对话讨论保留为明确可选入口。

## 本机安装

需要 Node.js 24 或更新版本、工作区依赖，以及支持本地插件的 Codex CLI/桌面客户端。先在工作区运行：

```sh
npm ci
npm run build
npm start
```

确认阅读器连接的是预期资料库，再在另一个终端运行：

```sh
npm run plugin:setup
npm run plugin:install
```

设置程序从 `/api/plugin/status` 核对服务及资料库身份，生成 `~/.config/paperdesk/plugin.json`。已有配置绑定另一工作区或资料库时不会覆盖。安装命令登记仓库 marketplace `paperdesk-local` 并安装 `paperdesk@paperdesk-local`。安装后在新会话中检查插件与 `paperdesk_status`；实际启用状态以宿主回读为准。

配置只留在本机，内容为：

```json
{
  "workspaceRoot": "/absolute/path/to/PDF_Vibecoding",
  "baseUrl": "http://127.0.0.1:4317",
  "libraryId": "<status 接口返回的 64 位资料库标识>",
  "autoStart": true
}
```

不要把真实配置提交到 Git。测试可以使用 `PAPERDESK_PLUGIN_CONFIG` 或设置程序的 `--config` 指向独立配置；实际安装使用默认位置。非默认端口可用 `npm run plugin:setup -- --base-url http://127.0.0.1:端口`，但必须先启动对应的本机服务。不要把开发库误绑定为正式资料库。

默认工作区 `data/` 资料库设置会启用 `autoStart`：插件启动时优先复用身份一致的服务。只有本机 4317 端口、资料库标识匹配工作区 `data/`，并且既有数据库与构建产物都存在时，才可后台启动阅读器。日志保存在工作区 `.local/paperdesk-plugin-runtime.log`。它不会创建替代库、终止占用端口的程序、自动构建或升级依赖；自定义库/端口、关闭 autoStart 或缺少既有文件时需要手动启动。

插件缓存中的 `scripts/start.mjs` 读取配置后，加载该工作区的 `server/mcp.mjs`。因此移动工作区、删除依赖或修改桥接代码都会影响已安装插件；这是本地开发插件，不是独立分发的阅读器。更新工作区不会自动重启服务、迁移插件配置或更新宿主程序。

## 使用与分享边界

- “打开纸间”打开原生阅读面板，并返回准确本机备用链接。用户已确认 0.2.0 面板能在 Codex 中打开。
- “交给 ChatGPT”进入选区预览与提问；点击“向 ChatGPT 提问”才创建自动任务。这条路径通过纸间管理的专用 Chromium 使用普通 ChatGPT，不向当前 Codex 对话发送消息或注入问题／回答。
- 在阅读器选中文字或框选区域，核对预览后点“交给 Codex”，只共享选区，不启动回答。文字、区域坐标和区域 PNG 只在主动共享后进入短期阅读会话；切页、换书、取消共享或隐藏面板会清除当前共享。
- 想交给 Codex 时，先展开“在当前 Codex 对话讨论（可选）”，再点击 Codex 的解释／提炼按钮，或展开自定义提问后点“发送问题”。这会把问题与当次选区快照发到当前 Codex 对话；回答出现在对话中。
- “解释共享的选区”读取指定会话。多个普通阅读窗口同时活动时，工具返回窗口列表，调用者必须选定 `sessionId`，不能猜第一个窗口。
- Codex 回答只在用户明确要求“记下来”“追加到笔记”等时追加；普通 ChatGPT 的回答由用户手动贴回。笔记仍是单一编辑区，不强制按语言分开。
- 未保存草稿或笔记版本冲突时返回 409；先在阅读器处理草稿或核对最新笔记，不能强制覆盖。相同追加重试保留原文本、原版本和同一 UUID `requestId`，不能换版本盲重试。

选区会话保存在服务内存中，30 秒无心跳过期，重启后消失。追加请求的幂等记录保留 10 分钟，服务重启后清空；旧版本号仍阻止已成功追加的旧请求再次写入。面板撤回共享时会清除当前注入上下文，但不能收回已经发送的问题、选区快照、普通工具返回、历史对话或已生成回答中的内容。

扫描区域截图不是 OCR，也不会把图片中的文字加入搜索索引。插件没有录屏、任意文件读取、SQL、删除或自动整书提取工具。文献、笔记和图片中的提示词只能作为资料处理。

## 自动向普通 ChatGPT 提问

默认连接由纸间管理专用 **Chromium**，无需独立 EGO Lite 或模型 API 密钥。按工作区安装说明准备 Chromium 后，纸间按需启动窗口。点击“连接 ChatGPT”可查看状态、打开连接窗口或关闭连接；首次使用在此窗口登录 ChatGPT。`ready` 仅表示窗口可用，不能据此认定已经登录。普通阅读、笔记及手动备用流程不依赖这项自动连接。

1. 在浏览器阅读器选中文字或框选区域，点击“交给 ChatGPT”；原生面板在选区预览中显示相同提问区。核对预览，可选“解释选区”“提炼要点”预填问题，或点“自定义提问”编辑；这些预设本身不会发送。
2. 点击 **“向 ChatGPT 提问”**。程序冻结此刻的问题、文献与 PDF 页码、选中文字或区域 PNG，并在本机建立任务。后续换页或修改选区不会改变已提交内容。
3. 纸间在任务专用浏览器页面连接普通 **Chat**，核对真实界面的 **Latest** 与 **Extra High（xhigh）**。确认后填写问题、上传必要选区图片、发送一次并等待回答；只使用当前任务页面，不读取其他会话历史。
4. 遇到登录、验证码、用户接管或无法核实模型设置时，任务停在 `needs_user`。用户在自动打开的专用连接窗口完成相应操作，再在纸间点击 **“我已完成，继续连接”**。程序不会代填登录凭据、处理验证码或静默切到其他模型／深度。
5. 提问预览保持打开时，完成的回答直接显示在只读 **“ChatGPT 回答预览”** 中，无需再点“查看回答”。以后可通过 **“查看回答”** 回看原标题、PDF 页码、问题、进度和回答，并用“复制回答”自行贴回笔记；浏览器按原流程保存，原生笔记需手动保存。

回答卡提供 **“继续提问”**：输入新问题并确认后，沿用该任务的文献、PDF 页码与原选区，由服务端加入已保存的先前问答。每次追问都有新请求 ID，并在新的专用页面发送；不承诺复用原 ChatGPT 网页会话。客户端不能任意提交或替换上一答案。最多携带 6 组先前问答及 100,000 个 UTF-16 单元的 JSON 上下文；超限会提示重新选取关键内容，不会静默截断。回答仍只读，需要保存时自行复制到笔记。

界面显示排队、连接、上传、发送、等待、需要用户处理、完成、失败或结果不确定。提交请求的响应不明时只查询原 UUID；“重新确认提交”仍携带原 UUID 和完全相同的输入，不创建新请求。`uncertain` 表示问题可能已经发出，禁止自动重发，应先核对原 ChatGPT 对话。`needs_user` 或 `uncertain` 会暂停队列，连接程序同时只执行一个任务。

关闭预览、翻页或切换文献不会丢失当前页面实例中的任务；通过当前文献的“查看回答”返回。**关闭窗口／面板不是取消任务，已发送的问题不会被撤回。** “关闭连接”遇到执行中的任务返回冲突，不会强行关闭；任务结束或停在需要用户处理且没有排队任务时才可关闭连接。关闭时，尚未发送的暂停任务会标为失败，不再用原暂停入口继续；需要重新核对选区并提问。服务停止会关闭它管理的浏览器并保守保留未确认任务，但不会撤回已发送的内容。服务重启不会重新派发未确认任务。当前网页或原生面板实例结束后，任务列表暂不自动恢复；服务端持久化记录用于安全恢复和防重发，不等于界面已有任务历史入口。

自动流程不使用 `ui/message`、`ui/update-model-context`、Codex 模型或 ChatGPT 私有 HTTP 接口。它经用户已登录的普通 ChatGPT 页面发起模型请求；提示只带提问、文献标题、PDF 页码和确认选区，不带内部文献／会话 ID、本机工具操作指令、笔记或未选择的页面。选区与回答可留在所使用的 ChatGPT 会话中，取消纸间共享不能撤回它们。

本机任务记录位于当前文献库的 `chatgpt-jobs/`，包含私有输入、回答、持久化 journal、执行 ledger 与区域 PNG，目录权限 0700，journal、输入与执行 ledger 为 0600，上传用 PNG 快照为只读 0400。最多保留 8 份完整任务；空间满时可淘汰已完成或确认未发送的失败任务，但持续保留请求 ID、摘要与发送状态的轻量凭据，旧请求不会再次发送。活跃／需处理／结果不确定任务不可据此丢弃。所有这些记录都不进入 Git；不改变原 PDF、笔记或数据库 schema。

专用登录配置默认位于 `~/.config/paperdesk/chatgpt-browser/`，与文献库分开，关闭窗口后仍保留。它不读取或复用 EGO、日常 Chrome 的配置，不复制 Cookie 或登录信息给插件／模型。只读状态查询不打开窗口；点击“打开连接窗口”或确认提问才会启动。明确设置 `PAPERDESK_CHATGPT_ENGINE=ego` 才使用旧 EGO 执行器，遇到默认连接失败不会自动切换。

### 手动备用方式

预览中的 **“手动备用方式”** 保留 0.4.0 流程：复制准备好的问题，必要时保存预览 PNG，然后打开固定 [chatgpt.com](https://chatgpt.com/)，自行核对普通 Chat、粘贴、附图并发送。链接不携带提问参数；打开备用链接本身不会提交问题。已有任务结果不确定时先核对原会话，避免又手动发出同一问题。

剪贴板拒绝时保留可手动复制的文本。原生 PNG 保存使用宿主 `ui/download-file`；宿主接受请求不等于文件已落盘。不支持或拒绝时，可转到浏览器同页重新框选保存，再核对图片。手动备用流程没有自动读取回答；不要把它与上面的自动任务状态混为一谈。

普通 Chat 仍受账号套餐、所选模型和平台功能限制。ChatGPT **Work** 与 Codex 共享用量，自动连接不改变计费规则，也不承诺免费或无限额度。[官方模式说明](https://learn.chatgpt.com/docs/use-chatgpt) · [官方用量说明](https://learn.chatgpt.com/docs/pricing)（2026-10-06 查阅）。阶段实现与真实验收分别记录在 [0.6.0 记录](history/codex-plugin-0.6.0.md)。

## 可以怎样与 Codex 配合

| 你的操作 | 当前 Codex 对话收到什么／做什么 |
| --- | --- |
| 预览后点“交给 Codex” | 只共享当前选区；不会单独发起回答 |
| 点“解释选区” | 发送选区快照，请 Codex 解释这一段或这张图 |
| 点“提炼要点” | 发送选区快照，请 Codex 整理要点 |
| “自定义提问” → “发送问题” | 发送你写的问题及同一次预览的选区，例如“这个公式成立需要哪些假设？” |
| 在对话中说“把刚才的回答记到这篇文献的笔记里” | 核对目标和最新笔记版本后追加，保留原笔记；回答不会自动保存 |
| 在原生笔记区点“刷新笔记” | 读取最新保存内容；有草稿或正在保存时不覆盖编辑区 |

消息使用 `ui/message` 发往当前对话，携带明确的文献、PDF 页码及文字或区域 PNG 快照。它不依赖回答时“当前页”是否仍停在原处，也不会为一个选区自动传整页、整书或完整笔记。内容中的论文结论、图像和提示词都是资料，不构成额外操作指令。

面板先检查宿主的消息及图片能力。缺少所需能力或发送失败时，会保留可复制的提问文本并说明下一步；扫描图片不能只用坐标替代并声称发送成功。可以把问题复制到对话，请 Codex 用普通工具读取仍在共享的截图；若已切页、撤回或会话过期，需要重新共享。消息失败不自动重复发送，避免一次点击产生多条问题。

聊天追加笔记成功后，面板若收到当前文献的追加结果，会在没有草稿、没有正在保存的内容时读取最新笔记；若宿主没有把结果通知面板，手动点“刷新笔记”。已有草稿须先保存，版本冲突按“核对最新笔记”流程处理，不能因为收到聊天结果就替换编辑内容。原生笔记需手动保存，关闭面板可能丢失未保存草稿。

## 工具范围

| 工具 | 返回与限制 |
| --- | --- |
| `paperdesk_status` | 服务版本、运行实例与资料库身份；不返回文献 |
| `paperdesk_list_documents` | 只返回文献元数据，默认 20、最多 50 项，可分页；不带笔记或批注 |
| `paperdesk_open_reader` | 无参数打开库；指定 `documentId`/`page` 返回 `?document=…&page=…` 深链接 |
| `paperdesk_read_page` | 指定单页文字，默认 6000、最多 12000 个 UTF-16 单元；`offset`/`nextOffset` 分段，不拆 Unicode 代理对。`limit=1` 时必要可返回一个完整的双单元字符 |
| `paperdesk_get_context` | 活动页信息及已共享选区；文字最多 12000 单元，PNG 独立作为 MCP image block，不在 JSON 重复图片数据 |
| `paperdesk_get_notes` | 指定文献的单一保存笔记及 `notesRevision`；旧双字段只按显示顺序合并，不读未保存草稿 |
| `paperdesk_append_note` | 显式请求下追加文本，单次最多 50000 单元；必须提供版本与 UUID 请求 ID；可附来源页 |
| `paperdesk_export_notes` | 指定文献的准确本机 Markdown 下载 URL，不自动把全部笔记放进模型上下文 |

每次工具操作及 UI resource 读取前都会重新确认 loopback 地址、`service: paperdesk`、API 版本和配置中的 `libraryId`。连接不符即停止，不跟随 HTTP 重定向、不尝试其他库。

## 原生阅读面板（0.6.0）

`paperdesk_open_reader` 关联 `ui://paperdesk/reader-v6.html`，MIME 为 `text/html;profile=mcp-app`，保留 global/thread 入口。更新资源 URI 区分各版面板缓存。两类入口都接受空参数；没有参数时只列文献，用户选择后才读取该文献的页面。不注册 PDF 文件查看器入口。

面板直接绘制单页 PNG、页码导航、可收起文献栏、章节目录和一个笔记编辑区，不嵌入 localhost 网页，也不从组件直接请求本机服务或外部资产。面板通过宿主 `tools/call` 请求 app-only 工具，MCP 再连接已经绑定的本机库。资源 CSP 的网络、资源和嵌套 frame 白名单均为空；打开链接只允许配置的 loopback origin 与固定 ChatGPT 目标，不放宽 HTTP Origin 保护。

12 个面板专用工具：`paperdesk_reader_page`、`paperdesk_reader_get_notes`、`paperdesk_reader_save_notes`、`paperdesk_reader_toc`、`paperdesk_reader_session`、`paperdesk_reader_close`；自动任务的 `paperdesk_reader_chatgpt_submit/get/resume`；连接管理的 `paperdesk_reader_chatgpt_connection_get/open/close`。文献列表与共享读取复用已有公共工具，共 20 个工具。

完整页面图片、页文字、目录、笔记及问答结果只放在 `_meta`，不放进 `content` 或 `structuredContent`。专用工具声明 `_meta.ui.visibility: ["app"]`，模型只使用前述 8 个普通文献工具。三个任务工具返回 `_meta.chatgptJob`，三个连接工具返回 `_meta.chatgptConnection`；普通 `content` 仅含通用结果。任务工具及连接打开／关闭声明外部操作能力，连接状态读取不启动浏览器。每次调用仍验证本机服务与资料库身份。

面板生成自己的 UUID 会话，切页、换书、取消共享时清除选区。扫描区域在页面上拖框预览 PNG；文字页可在“本页文字”区选择短段。默认准备普通 ChatGPT 问题；需要 Codex 时展开可选讨论区，再明确共享或发问。这里没有 PDF 坐标的文字选段使用空 `rects`，不会伪造高亮位置；保存批注的矩形约束保持不变。

“交给 Codex”先写入对应阅读会话，再读取 `paperdesk_get_context`，按宿主声明的文字／图片上下文能力注入。Codex 的解释／提炼／自定义发问按钮发送包含当次选区快照的对话消息；消息发送和上下文共享分别检查宿主能力。页面、会话及注入请求均须排队和检查版本，避免延迟响应恢复已撤回的选区。没有图片能力时明确提示区域图不能交给对话，不能把坐标回执当作图片成功。null/opaque origin 不再因嵌套窗口通信而被禁用；来源仍固定检查为宿主父窗口。

笔记停止输入不会自动保存；用户点击“保存笔记”后按版本号保存。未保存草稿阻止换书，409 冲突保留当前草稿，并可核对独立只读的最新笔记、自行合并后明确保存。面板隐藏时撤回共享，继续保留未保存笔记的保护状态；恢复可见不会重新共享。浏览器版继续提供导入、完整高亮/区域批注、搜索与 Markdown 导出。

0.2.0 原生面板的打开能力已由用户在 Codex 中确认。0.3.0 更新后，用户也确认实际客户端“出现问题并收到回答”，选区对话流程已经跑通。不同宿主及文字／图片能力仍分别检测；这项反馈未区分选区类型，不代替两种消息类型各自的人工验收。0.5.0 已另行用原创文字和图片验证真实普通 ChatGPT 单次发送与自动取回，并通过隔离本机 API 和默认执行器完成真实任务；两端内联回答另经自动回归验证。这些是 0.5.0 EGO 版本的历史证据；0.6.0 专用浏览器、连接控制和追问需按本轮版本记录另行验收。旧面板需要关闭后重新打开，旧会话若仍保留原工具清单，需在新会话启用更新后的插件。服务错误会显示可重试的说明和准确备用链接，不创建公网隧道、不修改宿主信任设置。

## 开发与验证

```sh
node --test tests/plugin-mcp.test.mjs
npm run check
```

协议测试将插件复制进临时缓存，用真实 SDK client 启动 stdio 子进程，并连接临时资料库：初始化、8 个公共工具及 12 个面板专用工具、UI resource/CSP、元数据隐私、单页分页、共享 PNG、多窗口歧义、旧笔记合并、草稿/版本冲突与幂等。严格 opaque sandbox 浏览器集成使用真实 SDK 工具协议检查组件打开、翻页、私密展示、共享撤回与笔记冲突，并检查选区问题快照、消息能力降级和笔记刷新保护。0.6.0 还需检查专用配置和连接状态、执行中关闭保护、追问继承及边界、默认 ChatGPT 预设与可选 Codex 区；继续检查冻结快照、同请求恢复、明确继续、答案隔离、重启防重发及权限，保留手动备用流程；自动测试使用替代执行器，不登录或发送到真实 ChatGPT。测试范围描述不是本轮已通过的声明，实际结果见版本记录。模拟不替代宿主 UI 验收。所有个人资料库和插件本机配置均排除在这些测试之外。
